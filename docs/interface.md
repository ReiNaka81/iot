# インタフェース仕様書 (Host A ↔ サーバ)

Host A (受信側 PC) からサーバ側へ加速度データを引き渡すための取り決め。
チームメンバはこの仕様に従ってサーバ側を実装すれば、Host A の実装と独立して開発できる。

---

## 1. 転送方式

| 項目 | 値 |
|---|---|
| プロトコル | FTP |
| ホスト     | `172.31.202.182` (サーバの IP、現状値。変更時は要連絡) |
| ポート     | 21 |
| ユーザー   | `user` |
| パスワード | `password` |
| 配置先     | サーバの FTP ルート (`/`) |

> 参考: 受信側 FTP サーバの起動コードは `final/server/ftp_server.py`。
> `RECV_DIR = "./recv"` がルートになるので、CSV はそこに直接置かれる。

---

## 2. ファイル

### 命名規則
```
accel_YYYYMMDD_HHMMSS.csv
```
例: `accel_20260514_142739.csv`

時刻は Host A のローカル時刻(JST想定)。

### 配置タイミング
- **10 秒に 1 回** Host A から push される
- 1 ファイルあたり **約 200 行** (20Hz × 10s)
- 1 行 1 サンプル

### 文字コード
UTF-8、改行 LF。

---

## 3. CSV スキーマ

ヘッダ + データ行。

```csv
timestamp,x,y,z
2026-05-14T14:27:39.420,0.020,0.100,1.040
2026-05-14T14:27:39.470,0.021,0.099,1.041
...
```

| カラム | 型 | 説明 |
|---|---|---|
| `timestamp` | ISO 8601 文字列 (ms精度) | サンプル取得時刻 (Host A 時計) |
| `x` | float | 加速度 X 軸 [G] |
| `y` | float | 加速度 Y 軸 [G] |
| `z` | float | 加速度 Z 軸 [G] |

- 単位は **G (重力加速度)**。静止時の z 軸は約 1.0 G になる。
- 分類状態 (STILL/WALK/RUN)、ノルム、分散などの**派生値は含めない**。MapReduce 側で計算する。

---

## 4. サーバ側の責務

チームメンバが実装する範囲:

1. **FTP サーバを稼働させ続ける**
   - `final/server/ftp_server.py` を起動
   - Host A からの接続を受け入れる
2. **`recv/*.csv` を監視**
   - 新しい CSV が来たら検出 (`watchdog` or 定期 ls で十分)
3. **MongoDB へ ingest**
   - DB: `iot`、Collection: `accel_raw`
   - 1 行 = 1 ドキュメント:
     ```json
     {"timestamp": "2026-05-14T14:27:39.420", "x": 0.02, "y": 0.10, "z": 1.04}
     ```
   - 既存ユーティリティ `final/server/csv_to_json.py` で CSV→JSON 変換可能
4. **取り込み済 CSV の保管**
   - `recv/` から `logs/` (またはそれに類するパス) に移動
   - アーカイブ目的。重複取り込み防止にもなる
5. **MapReduce**
   - 入力: MongoDB の `accel_raw`
   - 詳細は `final/docs/design.md` の §6 を参照

---

## 5. データ受け渡しの確認手順 (疎通テスト)

1. サーバ側で `ftp_server.py` 起動
2. Host A で `receiver.py --port COMx` 起動
3. 10秒待つ
4. サーバ側 `recv/` に `accel_*.csv` が現れることを確認
5. 中身が `timestamp,x,y,z` ヘッダ + 約200行であることを確認

これに加えて `final/server/test/sample.csv` (60行 / STILL+WALK+RUN を含む手動作成データ) を、
MapReduce 開発時の固定入力として使える。
